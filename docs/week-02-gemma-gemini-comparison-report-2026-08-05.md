# Week 2 Gemma–Gemini 비교 결과

이 보고서는 같은 질문과 같은 평가 기준으로 두 VLM 호출 경로(route)를 비교하는 방법을
학습하기 위한 자료다. 결과는 수업용 AIHub 질문 40건에 한정되며, 모델의 일반적인 우열이나
배포 가능성을 증명하지 않는다.

## 학습 목표

- 모델 비교 전에 입력, 지시문(prompt), 출력 형식(schema)과 채점 기준을 고정하는 이유를 이해한다.
- 정해진 규칙으로 계산하는 점수와 API 제공사 오류를 분리한다.
- 상대 비교의 `pass`와 실제 사용 승인 판단이 다른 이유를 이해한다.

## 비교 계약

| 고정한 항목 | 내용 |
| --- | --- |
| 데이터 | 같은 AIHub 질문 40건 |
| 입력 | 같은 질문과 같은 페이지 JPEG |
| 지시문(prompt) | 두 호출 경로가 함께 사용할 수 있는 JSON 전용 지시문 |
| 출력 형식 | 같은 JSON 구조(schema) |
| 채점 | 같은 `aihub-vqa-deterministic-v2` |
| 바꾼 항목 | API 제공사와 모델 호출 경로 |

PDF 추출 문장은 모델 입력과 고정 규칙 채점에 사용하지 않았다. OCR과 문서 이해는 VLM이 페이지
JPEG에서 수행한다.

전체 성공(`task_success`)은 출력 형식 통과(`schema_validity`), 답변 보류 판정
(`abstention_correct`), 정답 판정(`answer_correct`), 근거 포함
(`evidence_coverage`)을 모두 통과할 때만 1이다.

문자열 유사도, 토큰(token) F1, 숫자 일치와 근거 페이지 F1은 실패 원인을 찾는 진단 지표다. 이 중
하나가 높다고 전체 성공으로 판정하지 않는다.

## 비교 전에 확인한 지시문 효과

같은 Gemma 4의 기준·개선 지시문 응답을 현재 채점기로 다시 계산했다.

| 확인 항목 | 기준 지시문 | 개선 지시문 |
| --- | ---: | ---: |
| 품질을 평가할 수 있는 사례 | 40 | 39 |
| API 제공사 오류 | 0 | 1 |
| 전체 성공 | 9/40, 22.5% | 28/39, 71.8% |
| 숫자 일치 | 40.0% | 84.6% |
| 출력 형식 통과 | 92.5% | 89.7% |
| 순수 JSON | 0.0% | 28.2% |

새 성공은 20건, 새 실패는 1건이었다. API 오류 1건은 품질 점수 0점으로 넣지 않고 비교
불가로 분리했다. 평균 개선은 크지만 새 실패와 비교 불가 사례가 있어 자동 판정은
판단 보류(`inconclusive`)다.

## 대표 사례 세 건

두 호출 경로에 같은 지시문과 이미지를 보내 먼저 세 가지 실패 유형을 확인했다.

| 사례 | Gemma | Gemini | 확인할 점 |
| --- | --- | --- | --- |
| `r01` | `71.6%`, 성공, 코드 블록으로 감싼 JSON | `71.6%`, 성공, 순수 JSON | 정답과 출력 형식을 따로 평가 |
| `r03` | `2.6%`, 성공, 코드 블록으로 감싼 JSON | `2.6%`, 성공, 순수 JSON | 같은 정답이어도 구조 준수는 다를 수 있음 |
| `r31` | `106.0`, 실패 | `93.6`, 실패 | 근거가 없을 때 숫자를 추측하지 않고 보류해야 함 |

세 사례에서 두 호출 경로의 전체 성공은 각각 2/3이었다. 사례 세 건만으로 전체 모델의 우열을
정할 수 없으므로 40건 전체 비교가 필요하다.

## 전체 비교 결과

| 확인 항목 | NIM Gemma | AI Studio Gemini |
| --- | ---: | ---: |
| 응답 | 40/40 | 40/40 |
| 전체 성공 | 27/40, 67.5% | 35/40, 87.5% |
| 순수 JSON | 8/40 | 40/40 |
| 출력 형식 통과 | 38/40 | 40/40 |
| 평균 응답 시간(latency) | 16,714ms | 2,487ms |
| 입력/출력 토큰(token) | 111,513 / 3,530 | 367,337 / 3,459 |
| API 제공사 오류·재시도 | 0 / 0 | 0 / 0 |
| 실제 처리 모델 불일치 | 0 | 0 |

Gemini의 전체 성공률은 20.0%p 높았다. 문제별 변화는 새 성공 8건, 새 실패 0건, 변화 없음
32건이다. Gemini는 모든 응답에서 순수 JSON과 출력 형식을 지켰지만, 절대 실패 5건이 남았다.

API 제공사마다 이미지와 토큰을 계산하는 방식이 다를 수 있으므로 입력 토큰 차이를 모델이
더 많은 정보를 사용했다는 뜻으로 해석하지 않는다. 비용을 비교할 때도 각 제공사의 실제
과금 규칙을 따로 확인해야 한다.

## 남은 실패 사례

| 사례 | 관찰 | 학습 포인트 |
| --- | --- | --- |
| `r07` | `3D프린트` 대신 `스마트 코리아`를 선택 | 모델의 정답 선택 실패 |
| `r27` | 기대 답을 포함한 더 긴 표현을 반환 | 허용할 의미 동등 표현을 먼저 정해야 함 |
| `r31` | 문서에 없는 기간의 값을 `93.6`으로 추측 | 답변 보류 실패 |
| `p01` | 같은 기간을 한국어 날짜 형식으로 반환 | 날짜 정규화 규칙을 점검해야 함 |
| `p07` | 기대보다 넓은 답과 잘못된 근거 페이지를 반환 | 정답과 근거를 함께 확인해야 함 |

`r31`은 두 호출 경로가 함께 실패한 핵심 사례다. 기대 동작은 이미지에서 질문의 기간을 확인할
수 없을 때 답변을 보류하는 것이다. 숫자 형식이 유효하더라도 보류·정답·근거 조건을
통과하지 못하면 전체 실패다.

`r27`과 `p01`은 모델 문제와 채점 규칙 문제를 구분해야 함을 보여 준다. 허용 표현을 결과를
본 뒤 임의로 넓히면 비교가 공정하지 않다. 다음 실행 전에 허용 기준을 먼저 고정해야 한다.

## 판정 읽기

상대 비교의 자동 상태는 `pass`다. 같은 비교 조건에서 Gemini에 새 실패가 없었기 때문이다.
하지만 `pass`는 모델 채택이나 실제 사용 승인을 뜻하지 않는다.

- Gemini의 절대 실패가 5건 남아 있다.
- 두 호출 경로 모두 중요한 답변 보류 사례 `r31`에서 실패했다.
- 따라서 출시 가능 주장 없음(`release_claim=false`), 실제 사용 판단은 보류(`HOLD`)다.

상대 개선과 절대 품질 기준을 분리하면 “기준보다 좋아졌다”와 “사용해도 된다”를 혼동하지
않을 수 있다.

이 결과는 코드 연습용 시험 전용(`test_only`) 자료다. 현재 API 제공사나 모델의 품질
증거로 사용하지 않는다.

| 장애 상황 | 처리 원칙 |
| --- | --- |
| 인증 실패 | API 제공사 오류로 기록하고 품질 분모에서 제외 |

| 반복 timeout | API 제공사 오류로 기록하고 품질 분모에서 제외 |

| 실제 처리 모델 불일치 | 응답은 보존하되 비교는 중단 |
