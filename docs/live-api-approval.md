# Week 1–2 실제 API 실행 승인 범위

실제 API 실습은 페이지 이미지를 모델 제공사의 서버로 보낸다. 이 문서는 전송 자료와 호출
상한을 실행 전에 확인하기 위한 학습자용 확인표다. 코드가 읽는 기준값은
[`configs/live-egress.yaml`](../configs/live-egress.yaml)에 있다.

## 호출 대상

| 실습 | API 제공자(provider) | 요청 모델 | 키 환경 변수 |
| --- | --- | --- | --- |
| Week 1 첫 작업 흐름 | NVIDIA NIM | `nvidia_nim/nvidia/nemotron-3-nano-omni-30b-a3b-reasoning` | `NVIDIA_NIM_API_KEY` |
| Week 2 지시문 A/B | NVIDIA NIM | `nvidia_nim/google/gemma-4-31b-it` | `NVIDIA_NIM_API_KEY` |
| Week 2 API 제공자 비교 | NVIDIA NIM·Google AI Studio | 위 Gemma·`gemini/gemini-3.5-flash-lite` | 두 제공자의 키 |

모델 목록과 무료 등급 조건은 바뀔 수 있다. 수업 당일 사전 점검(preflight) 결과와 계정의
할당량(quota)을 다시 확인한다.

## 보내는 자료와 보내지 않는 자료

| 보낸다 | 보내지 않는다 |
| --- | --- |
| AIHub PDF에서 만든 페이지 JPEG | PDF 추출 문장 |
| 한국어 질문 | 기대 정답과 채점 결과 |
| 구조화 답변용 지시문(prompt) | 다른 API 제공자의 응답 |
|  | API 키 |

VLM이 페이지 이미지를 직접 읽는 실습이므로 PDF 추출 문장은 모델 입력과 채점에 사용하지
않는다. AIHub 이용정책과 각 API 제공자의 데이터 이용 조건을 확인한 뒤 실행한다.

## 실행 전에 확인할 것

1. 전송 자료와 목적지가 승인 범위 안에 있다.
2. 사전 점검에서 요청 모델이 현재 목록에 있다.
3. `.env`에 필요한 키가 있고 Git에 포함되지 않는다.
4. 요청·토큰·비용·시간 상한과 재시도 횟수가 명령에 모두 있다.
5. `git status --short` 결과가 비어 있고 새 결과 폴더를 사용한다.

Git 상태 검사는 실행한 코드와 지시문을 나중에 다시 찾기 위한 안전장치다. 수업 중 파일을
수정했다면 저장하고 커밋한 뒤 실제 API를 호출한다.

## 승인된 상한

| 실행 | 요청 수 | 입력 토큰 | 출력 토큰 | 비용 | 시간 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Week 1 사전 실행 | 1 | 20,000 | 500 | USD 0.01 | 120초 |
| Week 1 전체 | 40 | 800,000 | 20,000 | USD 0.01 | 7,200초 |
| Week 2 지시문별 사전 실행 | 1 | 20,000 | 500 | USD 0.01 | 120초 |
| Week 2 지시문별 전체 | 40 | 800,000 | 20,000 | USD 0.01 | 7,200초 |
| Week 2 두 제공자 사전 비교 | 2 | 40,000 | 1,000 | USD 0.01 | 240초 |
| Week 2 두 제공자 전체 비교 | 80 | 1,600,000 | 40,000 | USD 0.01 | 3,600초 |

소규모 사전 실행(probe)은 원응답, 실제 처리 모델, 토큰과 오류를 확인하는 실행이다. 일부
사례가 성공했다고 전체 품질이 좋다고 결론 내리지 않는다.

## 결과 해석

저장 응답을 사용한 결과는 시험 전용 증거(`test_only`)다. 실제 API를 호출하고 대체 경로와
재실행을 끈 결과만 실제 품질 증거(`live_quality`)로 사용한다.

정상 응답이 채점 기준을 통과하면 `passed`, 실패하면 `failed`다. API 오류나 실제 처리
모델 불일치는 품질을 판정할 수 없으므로 `inconclusive`로 남긴다. 자동 통과는 출시 승인이
아니며, 마지막 채택 여부는 사람이 사례별 차이를 확인해 결정한다.
